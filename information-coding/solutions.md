# Идеи решений

Задачи показывают три разных способа использовать словарь или избыточность в
кодировании. В коде Хэмминга дополнительные биты позволяют исправить ошибку.
Хаффман использует известные заранее частоты символов, а LZW строит словарь
повторяющихся фраз непосредственно во время чтения сообщения.

## 1. Исправление посылки

### Идея

Для каждого проверочного бита можно отдельно вычислить, нарушена ли
соответствующая проверка на чётность. Однако все результаты удобно получить
одним проходом.

Рассмотрим `XOR` номеров всех позиций, на которых записана единица:

```text
syndrome = i1 XOR i2 XOR ... XOR ik.
```

Каждый бит числа `syndrome` равен чётности количества выбранных номеров,
содержащих единицу в соответствующем разряде. Это в точности одна из проверок
кода Хэмминга. У корректного слова все проверки дают чётную сумму, поэтому его
синдром равен нулю.

Если бит в позиции `e` изменился, принадлежность всех остальных позиций
проверочным группам не меняется. Проверка с номером `j` меняет результат тогда
и только тогда, когда в двоичной записи `e` установлен бит `j`. Поэтому синдром
повреждённого слова равен номеру `e`.

Алгоритм:

1. Положить `syndrome = 0`.
2. Для каждой позиции `i`, содержащей единицу, выполнить `syndrome ^= i`.
3. Если синдром ненулевой, изменить бит в найденной позиции.
4. Выписать биты исправленного слова, номера которых не являются степенями
   двойки.

Число `i > 0` является степенью двойки тогда и только тогда, когда
`(i & (i - 1)) == 0`.

### Доказательство корректности

Если ошибки нет, входное слово корректно. Каждая проверочная группа содержит
чётное число единиц, поэтому каждый бит синдрома равен нулю. Алгоритм выводит
позицию `0` и не изменяет слово.

Пусть ошибка находится в позиции `e`. Для каждого разряда `j` результат
проверки меняется тогда и только тогда, когда позиция `e` входит в
соответствующую группу. Это происходит тогда и только тогда, когда бит `j`
числа `e` равен единице. Следовательно, все биты синдрома совпадают с битами
числа `e`, то есть `syndrome = e`.

Алгоритм меняет бит именно в позиции `e` и восстанавливает исходное корректное
слово. После удаления проверочных позиций остаются ровно информационные биты в
исходном порядке. Значит, все строки ответа корректны.

### Сложность

Слово просматривается два раза. Время работы составляет `O(n)`, дополнительная
память, не считая строк с входом и ответом, — `O(1)`.

### Типичные ошибки и крайние случаи

- считать позиции с нуля вместо единицы;
- не включать сам проверочный бит в его проверочную группу;
- использовать сумму номеров вместо побитового `XOR`;
- исправлять бит при нулевом синдроме;
- считать позицию `0` степенью двойки;
- удалить из информационного слова не все позиции `1, 2, 4, 8, ...`.

Минимальный случай `r = 2` имеет длину `3` и один информационный бит. Ошибка
может находиться как в информационной, так и в проверочной позиции. Отдельно
стоит проверить уже корректное слово.

## 2. Код Хаффмана

### Идея

Сначала подсчитаем частоты букв. Каждая встретившаяся буква образует одно
дерево, вес которого равен её частоте.

Состояние алгоритма — лес уже построенных деревьев. Для каждого дерева хранятся
его вес и наименьшая буква среди листьев. Все деревья находятся в очереди с
приоритетом, упорядоченной сначала по весу, затем по наименьшей букве.

На каждом шаге извлекаются два первых дерева. Первое становится левым сыном
новой вершины, второе — правым. Вес новой вершины равен сумме весов сыновей, а
её наименьшая буква — минимуму наименьших букв сыновей. Новое дерево
возвращается в очередь.

Когда остаётся одно дерево, обойдём его в глубину. При переходе к левому сыну
добавим к коду `0`, при переходе к правому — `1`. В листе сохраним получившийся
код буквы. Единственному листу по соглашению задачи присваивается код `0`.

После построения таблицы проходим исходную строку и заменяем каждую букву её
кодом.

### Доказательство корректности

Каждой букве соответствует лист двоичного дерева. Путь до одного листа не может
быть началом пути до другого листа, поскольку лист не имеет потомков. Поэтому
полученный код является префиксным.

Покажем оптимальность для случая хотя бы двух различных букв. В полном
двоичном дереве есть два соседних листа максимальной глубины. В некотором
оптимальном дереве на их места можно поставить два объекта наименьшего веса:
обмен с более тяжёлыми объектами, расположенными не глубже, не увеличивает
стоимость.

Объединим эти два объекта в один с суммарным весом. Во всех кодовых словах
внутри пары появляется ровно один дополнительный бит, поэтому вклад
объединения равен сумме их весов. Оставшаяся задача совпадает с построением
оптимального дерева для уменьшенного набора объектов.

Таким образом, жадное объединение двух объектов наименьшего веса может быть
первым шагом оптимального решения. Повторяя рассуждение по индукции, получаем
оптимальность дерева Хаффмана. Сравнение по букве лишь однозначно выбирает один
из равноправных вариантов и не меняет стоимость.

Обход дерева записывает биты пути к каждому листу, а последний проход заменяет
каждую букву найденным кодом. Поэтому программа выводит именно требуемую
таблицу и правильное кодирование строки.

### Сложность

Пусть `k` — число различных букв, а `L` — длина закодированной строки. Подсчёт
частот занимает `O(n)`. Выполняется `k - 1` объединений по `O(log k)`. Обход
дерева требует `O(k)`, а формирование результата — `O(L)`.

Итоговое время равно `O(n + k log k + L)`. Таблица может содержать коды длины
до `k - 1`, поэтому память составляет `O(n + k^2)`, включая входную строку.
Для алфавита из 26 букв величина `k` ограничена константой.

### Типичные ошибки и крайние случаи

- использовать `priority_queue` как максимальную очередь;
- не учитывать правило разрешения равных весов;
- перепутать левого и правого сыновей;
- сравнивать внутреннее дерево не по минимальной букве всего дерева;
- оставить пустой код для строки из одной различной буквы;
- вывести таблицу не в алфавитном порядке.

Для строки из повторений одной буквы дерево состоит из одного листа, а
закодированная строка состоит из `n` нулей.

## 3. LZW-кодирование

### Идея

Каждая новая фраза LZW создаётся из уже известной фразы и одного символа.
Поэтому фразу-кандидата необязательно хранить как строку. Её можно описать
парой

```text
(код текущей фразы, следующий символ).
```

Будем хранить отображение из таких пар в коды добавленных фраз. Переменная
`cur` содержит код текущей фразы. В начале это код первого символа строки.

Для очередного символа `c` рассматривается пара `(cur, c)`:

- если пара уже есть в словаре переходов, фраза продолжается и `cur`
  заменяется кодом найденной фразы;
- если пары нет, текущая фраза является максимальной известной фразой. Её код
  добавляется в ответ, новая фраза `(cur, c)` — в словарь, а символ `c`
  становится новой текущей фразой.

После обработки строки код последней текущей фразы нужно добавить в ответ.

Словарь LZW префиксно замкнут: перед добавлением фразы `w + c` фраза `w` уже
находится в словаре. Поэтому, если `w + c` в словаре нет, в нём не может быть и
более длинной фразы, начинающейся с `w + c`. Значит, `w` действительно является
самым длинным известным префиксом.

### Доказательство корректности

Поддерживается следующий инвариант: перед обработкой очередного символа уже
выведенные коды описывают некоторый префикс исходной строки, а `cur` является
кодом находящейся в словаре фразы, совпадающей с ещё не выведенной обработанной
частью строки.

Если переход `(cur, c)` существует, объединённая фраза уже есть в словаре.
Алгоритм заменяет `cur` её кодом, поэтому инвариант сохраняется.

Если перехода нет, текущая фраза является самым длинным известным префиксом.
Алгоритм выводит её код, добавляет текущую фразу вместе с `c` под очередным
свободным кодом и оставляет `c` началом следующей фразы. Инвариант снова
выполняется.

После просмотра всей строки `cur` хранит код единственной ещё не выведенной
фразы. Добавив его в ответ, алгоритм кодирует всю строку. Следовательно,
полученная последовательность совпадает с результатом заданного алгоритма LZW.

### Сложность

Для каждого символа выполняется одна операция со `std::map`. В словаре не более
`|s| - 1` новых фраз. Время работы составляет `O(|s| log |s|)`, память —
`O(|s|)`.

### Разбор примера

Для строки `ABABABA` словарь изменяется так:

| Текущая фраза | Следующий символ | Результат |
|---|---|---|
| `A` | `B` | вывести `0`, добавить `AB = 26` |
| `B` | `A` | вывести `1`, добавить `BA = 27` |
| `A` | `B` | перейти к `AB = 26` |
| `AB` | `A` | вывести `26`, добавить `ABA = 28` |
| `A` | `B` | перейти к `AB = 26` |
| `AB` | `A` | перейти к `ABA = 28` |
| `ABA` | конец строки | вывести `28` |

### Типичные ошибки и крайние случаи

- начинать нумерацию новых фраз не с `26`;
- добавлять новую фразу, когда переход уже существует;
- после отсутствующего перехода начинать новую фразу не с текущего символа;
- забывать вывести код последней фразы;
- добавлять элемент в словарь после окончания строки;
- считать, что требуется битовая упаковка кодов.

Строка длины один даёт ровно один исходный код. Для строки из одинаковых
символов фразы постепенно удлиняются.
