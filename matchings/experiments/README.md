# Замеры Куна

Этот стенд предназначен для обсуждения после самостоятельной реализации
оптимизаций. Эталон `../01_school_dance.cpp` остаётся базовым.

Файлы `sparse.txt` и `dense.txt` сохранены 28 сентября 2026 года из
[разреженного теста](https://pastebin.com/raw/Sr9hexwU) и
[более плотного теста](https://pastebin.com/raw/0jydWU6k), указанных в плане
семинара. Содержимое и порядок рёбер сохранены, окончания строк приведены к LF.
Первый тест содержит доли по 50000 вершин и 1000 различных рёбер, второй
доли по 1000 вершин и 30000 различных рёбер. Нумерация с единицы.

Формат обоих файлов:

```text
n m
k
a_1 b_1
...
a_k b_k
```

Отдельный тест с неравными долями стенд строит сам: `n = 100000`, `m = 100`,
ребро из каждой левой вершины `a` в `a % 100` при нумерации с нуля.
Все шесть вариантов сохраняют исходный порядок соседей и не используют
досрочную остановку при насыщении меньшей доли.

Из каталога `matchings`:

```sh
clang++ -std=c++17 -O2 -Wall -Wextra -Wpedantic \
  experiments/bench.cpp -o /tmp/matching_bench
/tmp/matching_bench experiments/sparse.txt experiments/dense.txt
```

Стенд выводит CSV:

- `variant`: сравниваемый вариант;
- `size`: размер найденного паросочетания;
- `median_ms`: медиана пяти независимых запусков в миллисекундах;
- `roots`: число корневых вызовов DFS;
- `edge_scans`: просмотры рёбер в DFS и, если он есть, жадном проходе;
- `clear_writes`: записи при повторных полных очистках `visitedA`;
- `greedy_pairs`: число пар, выбранных жадным проходом.

Однократная инициализация массивов включена во время, но не в `clear_writes`.
Записи при посещении отдельных вершин также не входят в этот счётчик.
Размеры счётчиков 64-битные: в разреженном тесте число записей при очистках
превосходит диапазон знакового `int`.

Чтение, построение и транспонирование графа, проверка ответа и вывод находятся
вне замера. Поиск, создание и инициализация рабочих массивов входят в замер.
Счётчики собираются отдельным проходом, который также прогревает данные.
Измеряемая версия компилируется без счётчиков внутри циклов. Перед каждым
поиском создаётся новое пустое паросочетание. Стенд проверяет существование
рёбер ответа, уникальность участников и совпадение размеров между вариантами.

Сравнения:

| Опыт | Первый вариант | Второй вариант |
|---|---|---|
| A | Метки, старт из доли 100000 | Метки, старт из доли 100 |
| B | Очистка перед каждым DFS | Метки поиска |
| C | Метки поиска | Метки и жадная инициализация |

При жадном старте стенд сразу отмечает занятые левые вершины. Корневые поиски
идут только из остальных. Рекурсивные поиски могут менять партнёров уже
занятых вершин.

Запишите модель процессора, версию компилятора, флаги и медианы. Повторите
эксперимент при другой нагрузке на машину. Различие времени само по себе
не доказывает улучшение худшей асимптотики. Замеры автора и точные счётчики
приведены в [results.md](results.md).
