# Персистентные структуры данных

Цель семинара — научиться сохранять старые версии структуры данных, разделяя
между версиями неизменяемые узлы. Сначала мы реализуем стек, затем массив на
дереве отрезков и используем этот массив для очереди.

Листок рассчитан на два семинара по 90 минут и домашнее задание. На первом
семинаре выполняются задачи 1–3, на втором — задача 4 и мини-задачи 4a, 4b.
Задача 5 — домашняя. Для одного семинара задачи 3, 4a и 4b можно выдать
готовым кодом и разобрать вместе со студентами.

Нужны односвязные списки, указатели, рекурсия и базовое дерево отрезков.
Эталонные решения написаны на C++17. Во всех задачах вход корректен,
`1 <= q <= 200000`, а хранимые значения — целые числа от `-10^9` до `10^9`.
Остальные ограничения указаны в задачах. Ответы однозначны.

В персистентных задачах действуют общие правила:

- Начальная версия имеет номер `0`.
- Каждая изменяющая команда создаёт новую версию. Номера присваиваются
  последовательно: `1, 2, 3, ...`, только изменяющим командам.
- Команда может обращаться к **любой уже созданной версии**, включая `0`.
  Исходная версия сохраняется и остаётся доступной.
- Чтение не создаёт версий. Номер версии не совпадает с номером команды.
- Разные номера версий могут обозначать одинаковое содержимое и даже
  ссылаться на одни и те же узлы.

Полное копирование структуры при каждом изменении не допускается: требуется
уложиться в оценки ниже. Для удобства обозначим
`L(n) = 1 + ceil(log2(n))`. Это позволяет записывать оценки и при `n = 1`.

## 1. Стек на списке

Реализуйте обычный стек целых чисел на односвязном списке. Изначально стек пуст.
Каждый узел должен хранить значение и указатель на следующий узел. Готовые
контейнеры стека или списка использовать нельзя.

Поддержите команды:

- `push x` — добавить `x` на вершину;
- `pop` — удалить вершину и вывести удалённое значение;
- `top` — вывести значение вершины, не меняя стек.

Команды `pop` и `top` даются только для непустого стека. Каждая операция должна
работать за `O(1)`. Память для узлов должна составлять `O(s)`, где `s` — текущий
размер стека; удалённые узлы нужно освобождать.

Формат ввода:

```text
q
command_1
...
command_q
```

Формат вывода:

Для каждой команды `pop` или `top` выведите одно число на отдельной строке.
Команда `push` ничего не выводит. Если запросов на вывод нет, вывод пуст.

Учебная цель — вспомнить, какие указатели меняются при добавлении и удалении
вершины. Это основа следующей задачи.

Файлы: `01_stack.cpp`, `01_stack.txt`, `01_stack.expected.txt`.

### На доске: история стека

Пока не пишите код. К пустому стеку версии `0` применили команды:

```text
push 0 10
push 1 20
push 1 30
pop 2
push 4 40
pop 3
```

Здесь первый аргумент — исходная версия; результат каждой строки получает
следующий номер версии. Нарисуйте отдельно дерево происхождения версий и
узлы списков с указателями на вершины всех версий. Одинаковые значения сами по
себе не означают, что узел один и тот же.

1. Выпишите содержимое версий `0`–`6` от вершины к основанию.
2. Отметьте общие узлы. Какие версии имеют один и тот же указатель на вершину?
3. Сколько узлов создано всего? Сколько новых узлов нужно каждой операции?
4. Какие действия из обычного `pop` теперь недопустимы?

## 2. Персистентный стек

Переделайте решение задачи 1 так, чтобы оно поддерживало все версии стека.
Версия `0` пуста. Поддержите команды:

- `push v x` — создать версию, добавив `x` на вершину версии `v`;
- `pop v` — создать версию, удалив вершину версии `v`;
- `top v` — прочитать значение вершины версии `v`.

Здесь `0 <= v <= k`, где `k` — число уже созданных версий, не считая начальной.
Для `pop` и `top` версия `v` непуста. И `push`, и `pop` создают новую версию,
даже если её содержимое совпадает с содержимым существующей.

Каждая команда должна работать за `O(1)`. Каждый `push` создаёт ровно один
новый узел списка; `pop` и `top` не создают узлов списка. Запись о новой версии
учитывается отдельно от узла. Общая память должна быть `O(q)`.

Формат ввода:

```text
q
command_1
...
command_q
```

Формат вывода:

- Для `push` выведите номер созданной версии.
- Для `pop` выведите номер созданной версии и удалённое значение через пробел.
- Для `top` выведите прочитанное значение.

Каждой команде соответствует одна строка вывода.

Учебная цель — отличить создание версии от создания узла и научиться работать
с ветвящейся историей, сохраняя старые версии.

Файлы: `02_persistent_stack.cpp`, `02_persistent_stack.txt`,
`02_persistent_stack.expected.txt`.

Устно: как добавить запрос `size v` за `O(1)`? Где можно хранить размер, чтобы
не проходить список? Нужно ли создавать узел для пустого стека? Реализовывать
этот запрос в данной задаче не требуется.

## 3. Массив на дереве отрезков

Дан массив `a` длины `n`, `1 <= n <= 100000`. Индексы идут от `0` до `n - 1`.
Реализуйте его хранение в дереве отрезков **на указателях**. Узел соответствует
полуинтервалу `[l, r)`, лист хранит один элемент. Внутренний узел содержит
указатели на двух детей. Суммы и другие агрегаты пока не нужны.

Напишите функции `build`, `getElement`, `setElement`. В привычных обозначениях
дерева отрезков последние две функции соответствуют точечным `query` и
`modify`. Если ваш прежний код хранит дерево в массиве, переделайте его на
указатели.

Поддержите команды:

- `get i` — вывести `a[i]`;
- `set i x` — присвоить `a[i] = x`.

В обеих командах `0 <= i < n`. Изменения выполняются в единственном текущем
массиве. Построение должно занимать `O(n)` времени и памяти, каждая команда —
`O(L(n))` времени. Дополнительные узлы при `set` не нужны.

Формат ввода:

```text
n q
a_0 a_1 ... a_(n-1)
command_1
...
command_q
```

Формат вывода:

Для каждой команды `get` выведите одно число на отдельной строке. Команда
`set` ничего не выводит. Если команд `get` нет, вывод пуст.

Учебная цель — подготовить дерево, в котором каждый узел можно адресовать
отдельно. По сравнению со стеком изменение теперь затрагивает путь в дереве.

Файлы: `03_array.cpp`, `03_array.txt`, `03_array.expected.txt`.

Для отладки можно написать функцию `print`, которая выводит листья слева
направо. Она не входит в формат команд; её вывод не должен попадать в ответ.
Какова её сложность по сравнению с `n` вызовами `getElement`?

## 4. Персистентный массив

Переделайте решение задачи 3. Начальный массив — версия `0`. Ограничения на
`n`, индексы и значения остаются прежними. Поддержите команды:

- `get v i` — вывести элемент с индексом `i` в версии `v`;
- `set v i x` — создать новую версию, отличающуюся от `v` значением `a[i] = x`.

Здесь `0 <= v <= k`, где `k` — число уже выполненных команд `set`.
Команда `get` не меняет структуру и не создаёт версию. Команда `set` создаёт
версию даже при присваивании того значения, которое уже записано в элементе.

### На доске: история массива

Сначала спроектируйте новую структуру на рисунке, без кода. Начальный массив
версии `0` — `[1, 2, 3, 4]`. Хотим выполнить команды:

```text
set 0 2 30
get 0 2
set 0 0 10
set 1 2 30
```

Используйте дерево, которое делит `[l, r)` в точке `floor((l + r) / 2)`.

1. Выпишите номера новых версий и содержимое каждой из них.
2. Нарисуйте корни всех версий и общие поддеревья.
3. Отметьте путь к изменяемому листу. Какие узлы можно оставить общими?
4. Сколько новых узлов потребуется каждому `set`, если всегда копировать
   весь путь, даже при присваивании прежнего значения? Сколько создаёт `get`?
5. Что сломается, если изменить лист в старом узле, а скопировать только корень?

После обсуждения реализуйте дерево на указателях с копированием пути
к изменяемому листу.
В базовом решении каждый `set` создаёт по одному узлу на каждом уровне этого
пути, включая корень и лист, даже если значение не изменилось. Старые узлы
менять нельзя. `get` не создаёт узлов дерева.

Построение должно занимать `O(n)` времени. Каждая команда должна работать за
`O(L(n))`, каждый `set` создаёт не более `L(n)` узлов. Общая память —
`O(n + q * L(n))`. Не требуется, чтобы `n` было степенью двойки.

Формат ввода:

```text
n q
a_0 a_1 ... a_(n-1)
command_1
...
command_q
```

Формат вывода:

- Для `get` выведите прочитанное значение.
- Для `set` выведите номер созданной версии.

Каждой команде соответствует одна строка вывода.

Учебная цель — освоить копирование пути и совместное использование неизменённых
поддеревьев. Объясните, почему память растёт на `O(L(n))`, а не на `O(n)`
при одном изменении.

Файлы: `04_persistent_array.cpp`, `04_persistent_array.txt`,
`04_persistent_array.expected.txt`.

## 4a. Очередь на списке

Реализуйте обычную очередь целых чисел на односвязном списке с указателями
`head` на первый элемент и `tail` на последний. Изначально очередь пуста.
В этой мини-задаче хранится только одно текущее состояние, без версий.
Каждый узел содержит значение и указатель на следующий узел. Готовые
контейнеры очереди или списка использовать нельзя.

Поддержите команды:

- `push x` — добавить `x` в конец очереди;
- `pop` — удалить первый элемент и вывести его значение;
- `front` — вывести первый элемент, не меняя очередь;
- `size` — вывести число элементов в очереди.

Команды `pop` и `front` даются только для непустой очереди. Команда `size`
разрешена и для пустой. Ограничения на `q` и значения — общие для листка.
Каждая команда должна работать за `O(1)`. Память для узлов — `O(s)`, где
`s` — текущий размер очереди; удалённые узлы нужно освобождать.

Формат ввода:

```text
q
command_1
...
command_q
```

Формат вывода:

Для каждой команды `pop`, `front` или `size` выведите одно число на отдельной
строке. Команда `push` ничего не выводит. Если запросов на вывод нет, вывод пуст.

Учебная цель — проследить изменения обоих концов списка и подготовиться
к обсуждению персистентной очереди. Обязательно проверьте удаление последнего
элемента и следующее за ним добавление в пустую очередь.

Файлы: `04a_linked_queue.cpp`, `04a_linked_queue.txt`,
`04a_linked_queue.expected.txt`.

### Обсуждение: почему с очередью сложнее?

Очередь добавляет элементы в конец и удаляет из начала. В персистентной очереди
и добавление, и удаление создают новую версию.

1. Возьмите реализацию из задачи 4a. Из очереди `[10, 20]` хотим получить
   две версии: `[10, 20, 30]` и `[10, 20, 40]`. Нарисуйте указатели до
   и после добавления. Какой общий узел попытались бы изменить обе операции?
   Достаточно ли скопировать только последний узел?
2. Вспомните очередь на двух стеках: добавляем во входной стек, а при пустом
   выходном переносим туда весь входной. Почему в обычной очереди суммарное
   время `m` операций составляет `O(m)`?
3. Пусть оба стека персистентны, но перенос выполняется целиком и его результат
   не кешируется. Создайте версию с `m` элементами во входном стеке и пустым
   выходным. Затем `m` раз удалите первый элемент **из этой же версии**,
   каждый раз создавая новую ветку. Сколько переносов будет выполнено?
   Получится ли оценка `O(1)` в среднем по всем выполненным командам?
4. Какие ещё представления обычной очереди вы знаете? Вспомните циклический
   массив. Что нужно хранить вместе с ним, чтобы отличать пустую очередь от
   полной?

Продвинутые реализации с постепенным переносом, в том числе конструкции на
пяти-шести стеках, оставим для дополнительного чтения после семинара. Для
домашнего задания достаточно уже построенного персистентного массива.

## 4b. Очередь на циклическом массиве

Реализуйте обычную очередь вместимости `c`, `1 <= c <= 100000`, на массиве
длины `c`. Изначально очередь пуста. Храните индекс начала `head` и текущий
размер `size`. Индексы массива идут от `0` до `c - 1`; после последней ячейки
снова используется первая. Хранится только одно текущее состояние, без версий.

Поддержите те же команды:

- `push x` — добавить `x` в конец очереди;
- `pop` — удалить первый элемент и вывести его значение;
- `front` — вывести первый элемент, не меняя очередь;
- `size` — вывести число элементов в очереди.

Перед `push` размер очереди меньше `c`. Перед `pop` и `front` очередь непуста.
`size` разрешён и для пустой очереди. Ограничения на `q` и значения — общие
для листка. Число добавлений за всё время может превышать `c`.

После выделения массива за `O(c)` каждая команда должна работать за `O(1)`.
Память — `O(c)`. Сдвигать все элементы при удалении или увеличивать массив
при добавлении нельзя. Готовый контейнер очереди использовать нельзя.

Формат ввода:

```text
c q
command_1
...
command_q
```

Формат вывода:

Для каждой команды `pop`, `front` или `size` выведите одно число на отдельной
строке. Команда `push` ничего не выводит. Если запросов на вывод нет, вывод пуст.

Учебная цель — отработать циклическую индексацию перед заменой обычного массива
персистентным. Объясните, почему после `pop` не нужно очищать ячейку. Обязательно
проверьте переход через конец массива, повторное заполнение и `c = 1`.

Файлы: `04b_circular_queue.cpp`, `04b_circular_queue.txt`,
`04b_circular_queue.expected.txt`.

## 5. Персистентная очередь на циклическом массиве · домашнее задание

Переделайте очередь из задачи 4b в персистентную. Вместимость равна `c`,
`1 <= c <= 100000`. Версия `0` пуста. В каждой отдельной версии одновременно
находится не более `c` элементов, но всего добавлений и версий может быть
гораздо больше `c`.

Используйте циклический массив длины `c`, представленный персистентным деревом
из задачи 4. Вместе с корнем каждой версии храните индекс начала очереди и её
размер. Поддержите команды:

- `push v x` — создать версию с элементом `x`, добавленным в конец версии `v`;
- `pop v` — создать версию без первого элемента версии `v`;
- `front v` — вывести первый элемент версии `v`;
- `size v` — вывести число элементов версии `v`.

Здесь `0 <= v <= k`, где `k` — число уже выполненных `push` и `pop`. Перед
`push` размер исходной версии меньше `c`. Перед `pop` и `front` она непуста.
`size` разрешён и для пустой очереди. При `pop` нужно также вывести удалённый
элемент. `push` и `pop` всегда создают новую версию; `front` и `size` не создают.

После построения за `O(c)` команды `push`, `pop`, `front` должны работать за
`O(L(c))`, а `size` — за `O(1)`. В базовом решении только `push` создаёт узлы
дерева, не более `L(c)` штук. Общая память — `O(c + q * L(c))`.

Формат ввода:

```text
c q
command_1
...
command_q
```

Формат вывода:

- Для `push` выведите номер созданной версии.
- Для `pop` выведите номер созданной версии и удалённое значение через пробел.
- Для `front` и `size` выведите ответ на запрос.

Каждой команде соответствует одна строка вывода.

Учебная цель — собрать новую структуру из уже реализованной и отделить версию
очереди от версии её внутреннего массива. Объясните, почему после удаления
не нужно очищать ячейку и почему запись в освободившуюся позицию не портит
старые версии. Обязательно проверьте переход через конец массива и случай
`c = 1`.

Файлы: `05_persistent_queue.cpp`, `05_persistent_queue.txt`,
`05_persistent_queue.expected.txt`.

## Примеры и проверка

В файлах `NN_name.txt` лежат примеры входа, а в `NN_name.expected.txt` — точный
ожидаемый вывод. Примеры персистентных задач включают обращения к старым версиям
и ветвление истории; примеры циклических очередей проверяют переход через конец
массива. В 4a и 4b дана одинаковая последовательность команд с одинаковым

Из каталога темы можно собрать и проверить решение так:

```sh
clang++ -std=c++17 -O2 -Wall -Wextra -Wpedantic \
  02_persistent_stack.cpp -o /tmp/persistent-stack
/tmp/persistent-stack < 02_persistent_stack.txt > /tmp/persistent-stack.out
diff -u 02_persistent_stack.expected.txt /tmp/persistent-stack.out
```

Остальные задачи проверяются аналогично. Разборы, ответы к упражнениям на доске
и материалы для чтения после семинара находятся в `solutions.md`.
