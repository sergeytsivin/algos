# Идеи решений

Все три задачи работают с пространством битовых строк, но исследуют его
по-разному. Эти методы не дают гарантии глобального оптимума. Корректность
эталонных решений означает, что они в точности воспроизводят заданную
эвристику, поддерживают правильное значение разреза и выводят допустимое
решение.

## 1. Несколько случайных стартов

### Идея

Естественная локальная окрестность разреза состоит из `n` состояний, полученных
переводом одной вершины. Из случайного разбиения движемся только по улучшающим
переходам. Один запуск может остановиться в слабом локальном оптимуме, поэтому
повторяем поиск из `r` состояний и сохраняем лучшее.

### Состояние и переход

Состояние — строка `side` и текущее число пересекающих разрез рёбер `value`.
Для вершины `v` значение `gain[v]` равно числу её рёбер к вершинам своей доли
минус число рёбер в другую долю. После перевода `v` рёбра первого вида войдут
в разрез, а рёбра второго выйдут, поэтому новое значение равно
`value + gain[v]`.

На каждой итерации вычисляются выигрыши всех вершин. Выбирается максимальный,
а при равенстве — вершина с меньшим номером. Переход выполняется только при
положительном выигрыше. После остановки разрез канонизируется, потому что
строка и её полная инверсия описывают один набор пересекающих рёбер.

### Валидность и свойство результата

Любая битовая строка задаёт допустимое разбиение. При переводе вершины
неинцидентные ей рёбра не меняются, а формула для `gain` точно учитывает каждое
инцидентное ребро. Следовательно, хранимое значение всегда равно ценности
текущего разреза.

Каждый переход увеличивает целочисленную ценность хотя бы на единицу, а она не
превосходит `m`, поэтому попытка завершится. В момент остановки для всех вершин
`gain <= 0`. Ни один одиночный перевод не улучшает ответ: найден 1-локальный
оптимум. Лучший из нескольких запусков не хуже каждого отдельного результата,
но глобальная оптимальность не гарантируется.

### Сложность

Начальная ценность и выигрыши одной итерации вычисляются за `O(n + m)`. В одной
попытке не более `m` улучшающих переходов. Время —
`O(r * m * (n + m))`, память — `O(n + m)`. При `m = 0` уточнённая оценка
времени равна `O(r * n)`.

### Типичные ошибки и крайние случаи

- `std::uniform_int_distribution` не соответствует требуемому правилу
  `gen() & 1U`.
- Повторная инициализация генератора перед каждой попыткой создаёт одинаковые
  старты.
- Неверный знак `gain` заставляет алгоритм двигаться в сторону ухудшения.
- Переход при нулевом выигрыше нарушает строгий рост и может создать цикл.
- Нарушение правила равенств меняет однозначный ответ.
- При `m = 0` все попытки заканчиваются сразу, но строки всё равно нужно
  канонизировать и сравнить.
- Изолированные вершины имеют нулевой выигрыш, однако участвуют в строке.
- При `r = 1` получается обычный локальный поиск из одного старта.

### Дополнительные оптимизации

После перевода вершины можно обновлять выигрыши только для неё и её соседей.
Для выбора максимального выигрыша подойдут очередь с приоритетами с ленивым
удалением или корзины для целых значений. Это ускоряет разреженные графы, но
усложняет поддержку правила разрешения равенств и не требуется в эталонном
решении.

## 2. Взвешенный разрез с отжигом

### Идея

Подъём только по улучшениям останавливается в 1-локальном оптимуме. Отжиг
иногда принимает ухудшающий ход и может покинуть такое состояние. По мере
охлаждения ухудшения принимаются реже, и поиск переходит от исследования к
закреплению решения.

В задаче используется целочисленное правило принятия. При потере `loss > 0`
переход принимается с вероятностью, близкой к
`temperature / (temperature + loss)`. Остаток от деления вносит небольшое
смещение, но оно является частью заданного воспроизводимого алгоритма.

### Состояние и переход

Текущее состояние состоит из стороны каждой вершины, веса разреза и
температуры. Отдельно хранятся лучший посещённый вес и соответствующая строка.
Это различие существенно: ухудшающий ход меняет текущее состояние, но не
должен портить ответ.

Состояние `xorshift64` тоже является частью алгоритма. На инициализацию всегда
расходуется ровно `n` значений. На каждом шаге одно значение выбирает вершину,
а ещё одно расходуется только при `gain < 0`.

При переносе `v` меняется вклад только инцидентных рёбер:

```text
gain = сумма весов рёбер из v к своей стороне
       - сумма весов рёбер из v к другой стороне.
```

Если ход принят, инвертируется сторона `v`, а к текущему весу прибавляется
`gain`. Неухудшающий ход принимается всегда. Для ухудшающего сравнивается
`next() mod (temperature + loss)` с `temperature`. После каждого шага
температура умножается на `cool_num / cool_den`, округляется вниз и
ограничивается снизу единицей.

### Валидность результата

Изначально вес считается по всем рёбрам. При переносе статус неинцидентных
рёбер не меняется, а `gain` учитывает изменение каждого инцидентного ребра.
После принятого перехода `value += gain` снова даёт точный вес. Отклонённый
переход не меняет состояние.

Лучший ответ обновляется только после принятого перехода с большим весом.
Значит, он всегда является посещённым допустимым разбиением и после остановки
имеет максимальный вес среди состояний этого запуска. Полная инверсия битов
сохраняет вес. Гарантии глобальной оптимальности нет.

### Сложность

Начальный вес вычисляется за `O(m)`. Один шаг просматривает список смежности
выбранной вершины и занимает `O(deg(v))`. Для `steps` шагов точная оценка —
`O(n + m + sum deg(v_i))`, грубая верхняя — `O(n + m + steps * n)`.
Память — `O(n + m)`.

### Типичные ошибки и крайние случаи

- Использование другого генератора или вещественной экспоненты меняет запуск.
- Дополнительный вызов генератора при `gain >= 0` сдвигает всю
  последовательность.
- Лучший ответ нельзя заменять при равном весе.
- После ухудшающего хода обновляется текущее состояние, но не лучший ответ.
- Температура охлаждается после шага, а не до выбора вершины.
- Для веса и произведения параметров охлаждения нужен `long long`.
- При `gain = 0` ход принимается без дополнительного случайного числа.
- Температура после охлаждения никогда не становится меньше единицы.
- Лучшим может остаться начальное разбиение, хотя выполнить нужно все шаги.

### Дополнительные оптимизации

Можно хранить выигрыши всех вершин и после переноса обновлять только выбранную
вершину и её соседей. Для свободной, не проверяемой по точному протоколу версии
эвристики полезны несколько запусков, адаптивное охлаждение и повторный нагрев
после долгого отсутствия улучшений. Эти изменения не входят в эталонный код.

## 3. Эволюция разрезов

### Идея

Одна особь — битовая строка, то есть готовый разрез. Её приспособленность равна
числу рёбер между разными долями. Вместо одной строки алгоритм хранит `P`
кандидатов. Турнирный отбор чаще выбирает сильных особей, скрещивание соединяет
части двух решений, а мутация поддерживает разнообразие. Элитизм гарантирует,
что лучшее найденное значение не уменьшается от поколения к поколению.

### Состояние и переходы

Для каждой особи хранятся строка `x` и уже вычисленная ценность `value`. В
состояние алгоритма входят текущая популяция и состояние `mt19937`. Отдельный
глобальный ответ не нужен: лучшая особь после сортировки без изменений
копируется в следующее поколение.

Начальная популяция состоит из случайных строк. После вычисления ценностей она
сортируется по убыванию приспособленности, затем лексикографически. Новое
поколение начинается с элиты. Для каждого оставшегося места дважды проводится
турнир размера три. Ребёнок получает префикс первого родителя и суффикс
второго, затем каждый бит независимо проверяется на мутацию. После
канонизации ценность ребёнка вычисляется один раз.

Полное новое поколение сортируется и заменяет старое. Поэтому родители
следующего поколения выбираются только из уже завершённой новой популяции.

### Валидность результата

Любая хромосома длины `n` задаёт разбиение. Инициализация, скрещивание и
мутация не меняют длину и всегда оставляют каждый бит равным `0` или `1`.
Канонизация инвертирует обе доли одновременно и не меняет разрез.

Функция приспособленности просматривает все рёбра и считает ровно те, у которых
биты концов различаются. Поэтому напечатанное значение равно ценности строки.
После `G` поколений первая особь отсортированной популяции является требуемым
результатом заданного алгоритма.

Элитизм сохраняет лучшую особь текущей популяции дословно. Лучшее значение не
убывает, а при равенстве не теряется лексикографически меньшая уже найденная
строка. Глобальная оптимальность при этом не гарантируется.

### Сложность

Оценка одной особи занимает `O(m)`. За поколение создаётся `P - 1` детей, что
требует `O(P * (n + m))` времени. Сортировка добавляет
`O(P log P * n)`, потому что сравнение строк при равных значениях может занять
`O(n)`. Общее время — `O((G + 1) * P * (m + n log P))`, память —
`O(P * n + m)`.

### Типичные ошибки и крайние случаи

- `uniform_int_distribution` меняет детерминированную последовательность.
- Лишний вызов `rng()` при `n = 1` сдвигает все следующие значения.
- Без лексикографического разрешения равенств турнир зависит от порядка
  равных элементов.
- Мутация элиты уничтожает гарантию неубывания лучшего результата.
- Вычисление приспособленности внутри компаратора замедляет сортировку.
- Вероятность `Q / 100` вместо `Q / 1000` делает мутацию слишком сильной.
- При `G = 0` ответ выбирается только из начальной популяции.
- При `m = 0` ценности всех особей равны нулю.
- При `Q = 0` мутаций нет, при `Q = 1000` мутируют все биты.
- При `n = 1` внутренней точки скрещивания нет и остаток по модулю `n - 1`
  брать нельзя.

### Дополнительные оптимизации

При малом `Q` ценность ребёнка можно обновлять по изменённым битам, аккуратно
избегая двойного учёта рёбер. Возможные расширения алгоритма — равномерное
скрещивание, несколько элит, удаление дубликатов и адаптивная мутация.
Меметический вариант после мутации доводит каждого ребёнка локальным поиском;
обычно он быстрее улучшает качество, но смешивает методы всех трёх задач и не
входит в эталонную реализацию.
