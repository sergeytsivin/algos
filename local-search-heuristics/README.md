# Эвристики для перебора с локальным поиском

Набор рассчитан на один-два семинара. Его цель — познакомиться с тремя
способами исследовать большое пространство решений: повторным локальным
поиском из случайных состояний, имитацией отжига и генетическим алгоритмом.
Во всех задачах используется максимальный разрез графа, поэтому между задачами
меняется именно стратегия поиска, а не комбинаторная модель.

Во всех задачах граф неориентированный и простой: петель и кратных рёбер нет,
вершины нумеруются от `1` до `n`. Разрез задаётся битовой строкой: вершины с
разными битами лежат в разных долях. Одна из долей может быть пустой. Строка и её
полное дополнение задают один и тот же разрез, поэтому перед выводом результат
канонизируется: первый бит должен быть равен `0`.

Ни одна из эвристик не обязана находить глобальный максимум. В каждой задаче
точно заданы генератор, порядок его вызовов и правила разрешения равенств.
Благодаря этому проверяется воспроизводимый запуск алгоритма, а примеры имеют
однозначный вывод. Полный перебор всех `2^n` разбиений не является
предполагаемым решением.

Эталонные решения написаны на C++17 и не требуют более нового стандарта.

## 1. Несколько случайных стартов

Дан простой неориентированный граф. Ценность разреза равна числу рёбер, концы
которых лежат в разных долях.

Выполните ровно `r` запусков локального поиска и выведите лучший найденный
разрез. Начальное разбиение каждого запуска строится последовательно для
вершин от `1` до `n`: создайте один генератор `std::mt19937 gen(seed)` и
присвойте очередной вершине бит `gen() & 1U`. Генератор не перезапускается
между попытками.

В каждой попытке повторяйте следующие действия:

1. Для каждой вершины вычислите `gain` — изменение ценности разреза после
   перевода только этой вершины в другую долю.
2. Выберите вершину с максимальным `gain`; при равенстве выберите вершину с
   меньшим номером.
3. Если максимальный `gain` положителен, переведите выбранную вершину и
   продолжите поиск. Иначе попытка закончена.

После завершения попытки канонизируйте строку. Из всех попыток выберите разрез
наибольшей ценности, а при равенстве — лексикографически меньшую каноническую
строку.

Ограничения:

- `2 <= n <= 200`;
- `0 <= m <= 1000`;
- `1 <= r <= 30`;
- `0 <= seed <= 2^32 - 1`;
- `1 <= u, v <= n`, `u != v`.

Формат ввода:

```text
n m r seed
u1 v1
...
um vm
```

Формат вывода:

```text
value
bits
```

В первой строке выведите ценность выбранного разреза. Во второй строке
выведите его каноническую битовую строку длины `n`; `i`-й бит относится к
вершине `i`.

Ответ однозначен благодаря фиксированному генератору и правилам разрешения
равенств. Учебная цель — реализовать поиск по окрестности из одиночных
переводов, увидеть зависимость от начального состояния и уменьшить её с
помощью нескольких случайных стартов.

Файлы:

- `01_multistart.cpp` — решение;
- `01_multistart.txt` — пример ввода;
- `01_multistart.expected.txt` — ожидаемый вывод.

## 2. Взвешенный разрез с отжигом

Дан простой неориентированный граф с положительными весами рёбер. Вес разреза
равен сумме весов рёбер, концы которых находятся в разных долях.

Выполните один запуск метода имитации отжига и выведите лучшее посещённое
разбиение. В отличие от первой задачи, алгоритм может временно уменьшать вес
разреза, чтобы выходить из локальных оптимумов.

Используйте 64-битный беззнаковый генератор `xorshift64`. Его состояние
изначально равно `seed`, а каждый вызов `next()` выполняет:

```text
state = state XOR (state << 13)
state = state XOR (state >> 7)
state = state XOR (state << 17)
```

Все операции выполняются над 64-битными беззнаковыми целыми с отбрасыванием
переполнения. Вызов возвращает новое значение `state`.

Сначала для каждой вершины `1, 2, ..., n` по одному разу вызовите `next()` и
положите её на сторону `(возвращённое значение) AND 1`. Начальное разбиение
считается посещённым. Затем выполните ровно `steps` шагов:

1. Положите `rnd = next()` и выберите вершину `1 + rnd mod n`.
2. Вычислите `gain` после переноса этой вершины в другую долю.
3. Если `gain >= 0`, выполните перенос. Иначе положите `loss = -gain` и
   `rnd = next()`. Выполните перенос тогда и только тогда, когда
   `rnd mod (temperature + loss) < temperature`.
4. Если новое разбиение строго лучше всех ранее посещённых, запомните его.
5. Замените температуру на
   `max(1, floor(temperature * cool_num / cool_den))`.

Разбиение с весом, равным лучшему, не заменяет ранее запомненное. После всех
шагов канонизируйте только лучший ответ.

Ограничения:

- `2 <= n <= 200`;
- `1 <= m <= min(2000, n * (n - 1) / 2)`;
- `1 <= steps <= 20000`;
- `1 <= temperature <= 10^9`;
- `1 <= cool_num < cool_den <= 1000`;
- `1 <= seed <= 2^64 - 1`;
- `1 <= wi <= 10^6`;
- `1 <= ui, vi <= n`, `ui != vi`;
- сумма весов всех рёбер не превосходит `2 * 10^9`.

Формат ввода:

```text
n m
steps temperature cool_num cool_den seed
u1 v1 w1
...
um vm wm
```

Формат вывода:

```text
value
bits
```

В первой строке выведите лучший найденный вес. Во второй строке выведите
каноническую битовую строку длины `n`.

Ответ однозначен: генератор, порядок вызовов и правило сохранения ответа заданы
полностью. Учебная цель — научиться принимать ухудшающие ходы с уменьшающейся
вероятностью и отделять текущее состояние от лучшего найденного.

Файлы:

- `02_annealing.cpp` — решение;
- `02_annealing.txt` — пример ввода;
- `02_annealing.expected.txt` — ожидаемый вывод.

## 3. Эволюция разрезов

Дан простой неориентированный граф. Ценность разреза равна числу рёбер, концы
которых лежат в разных долях. Выполните генетический алгоритм и выведите лучший
разрез после `G` поколений. Теперь одновременно поддерживается популяция
решений, а новые решения создаются отбором, скрещиванием и мутацией.

Используйте `std::mt19937 rng(seed)`. Каждый остаток от деления ниже вычисляйте
непосредственно из очередного значения `rng()`; не используйте
`uniform_int_distribution`.

Сначала создайте `P` хромосом. Для каждой хромосомы и каждой вершины по порядку
вызовите генератор и положите `x[i] = rng() % 2`, затем канонизируйте строку.
Сравнивайте особей по убыванию ценности, а при равенстве — по возрастанию
битовой строки. Начальную популяцию отсортируйте этим сравнением.

Постройте ровно `G` поколений:

1. Скопируйте лучшую особь текущего поколения в новое без изменений.
2. Пока в новом поколении меньше `P` особей, создавайте по одному ребёнку.
3. Для каждого родителя трижды независимо вычислите индекс `rng() % P` и
   выберите лучшую из трёх особей. Повторы и одинаковые родители разрешены.
4. При `n >= 2` вычислите точку скрещивания
   `c = 1 + rng() % (n - 1)`. Первые `c` битов возьмите у первого родителя,
   остальные — у второго. При `n = 1` положите `c = 1`; генератор здесь не
   вызывается.
5. Для каждого бита ребёнка вызовите генератор и инвертируйте бит, если
   `rng() % 1000 < Q`.
6. Канонизируйте ребёнка, вычислите его ценность и добавьте в поколение.

После построения полного поколения отсортируйте его. После `G` поколений
выведите первую особь текущей популяции. Одинаковые хромосомы могут одновременно
находиться в популяции и не удаляются.

Ограничения:

- `1 <= n <= 100`;
- `0 <= m <= min(1000, n * (n - 1) / 2)`;
- `2 <= P <= 100`;
- `0 <= G <= 500`;
- `0 <= Q <= 1000`;
- `0 <= seed <= 2^32 - 1`;
- `1 <= ui, vi <= n`, `ui != vi`.

Формат ввода:

```text
n m P G Q seed
u1 v1
...
um vm
```

Формат вывода:

```text
value
bits
```

В первой строке выведите ценность лучшей особи, а во второй — её каноническую
битовую строку длины `n`.

Ответ однозначен: генератор, сравнение особей и порядок случайных действий
зафиксированы. Учебная цель — реализовать полный цикл генетического алгоритма:
представление хромосомы, функцию приспособленности, турнирный отбор,
одноточечное скрещивание, мутацию и элитизм.

Файлы:

- `03_genetic.cpp` — решение;
- `03_genetic.txt` — пример ввода;
- `03_genetic.expected.txt` — ожидаемый вывод.

## Сборка и запуск

Каждое решение можно собрать и проверить отдельно. Например:

```sh
clang++ -std=c++17 -O2 -Wall -Wextra -Wpedantic \
  01_multistart.cpp -o 01_multistart
./01_multistart < 01_multistart.txt
```

Вывод должен точно совпасть с соответствующим файлом `expected.txt`. Остальные
решения проверяются аналогично. Идеи, обоснования и типичные ошибки разобраны в
`solutions.md`.
